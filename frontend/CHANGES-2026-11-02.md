# Changes - 2026-11-02 (backend integration catch-up)

Made while the frontend team is unavailable, to bring this dashboard
in line with the current backend. Everything else is untouched.

## What changed in this repo

1. **Alert evidence (photo + video clip)** - the alert drawer now
   shows the real detection photo and the ~10 s clip instead of the
   "Photo pending" box:
   - `src/types/api.ts` - `Alert` gained `snapshot_url` and
     `clip_url` (null until the evidence file reaches the backend).
   - `src/features/dashboard/api/dashboardApi.ts` - new `mediaApi.blob()`.
     Evidence URLs need the bearer token, so the files are fetched
     as blobs through the shared axios client (a plain `<img src>`
     cannot send the Authorization header).
   - `src/features/dashboard/hooks/useAlerts.ts` - new
     `useMediaObjectUrl()` hook (creates/revokes object URLs).
   - `src/features/dashboard/components/AlertDrawer.tsx` - new
     `Evidence` component: photo, then clip with controls; keeps the
     "Photo pending" state while the upload is in flight (the drawer
     polls, so evidence appears automatically) and the "No evidence"
     state for alerts without files.
2. **`FRONTEND_API_GUIDE.md` refreshed** to the current backend
   contract (adds the "Alert evidence" section; the bundled copy was
   from 01-11).

## What changed on the backend (separate package)

- **CORS is now enabled** (`CORSMiddleware`, origins from
  `CORS_ORIGINS`, default `http://localhost:5173,http://127.0.0.1:5173`),
  as this repo's README requires. Use the updated backend package.
  For a deployed dashboard, add its origin to `CORS_ORIGINS`.

## Audit result

All other calls in `src/features/**/api` were checked against the
current backend routes (auth, alerts + lifecycle, users, officers,
wards + import, vehicles, settings, audit, stats, hotspots, reports,
officer tasks, ICCC stub) - no path or payload changes were needed.
